01

Automatiser la sauvegarde d'un parc de serveurs Linux

Problème Solution Impact

Le problème

Des sauvegardes manuelles et non fiables sur un parc de serveurs Linux : risque de perte de données, aucune visibilité sur l'état des disques et des services, et des heures d'intervention à répétition.

La solution

  • Scripts Bash + Python de sauvegarde incrémentale avec rotation et compression chiffrée.
  • Supervision en temps réel (CPU, RAM, disque, services) avec alertes automatiques sur seuils critiques.
  • Journalisation centralisée et tableau de bord de fiabilité.

L'impact mesuré

Réduction de ~60 % des interventions manuelles, restauration rapide après incident et zéro perte de données sur la période test.

02

Concevoir un chiffrement symétrique sûr en Python et Rust

Problème Solution Impact

Le problème

Besoin de valider les principes cryptographiques sans réinventer la roue : beaucoup d'implémentations amateurs souffrent de clés faibles, d'IV réutilisés ou d'absence de tests.

La solution

  • Chiffrement AES-256-GCM avec gestion stricte des clés et IV aléatoires par message.
  • Double implémentation Python et Rust, interopérable, déployée en environnement isolé.
  • Suite de tests unitaires couvrant chiffrement, déchiffrement et cas limites.

L'impact mesuré

100 % de couverture de tests, interopérabilité Python ↔ Rust validée, conformité aux bonnes pratiques de codage sécurisé.

03

Construire une application de gestion de stock de bout en bout

Problème Solution Impact

Le problème

Une gestion de stock réalisée dans des feuilles de calcul : erreurs de saisie, pas d'historique fiable, pas d'alertes de réapprovisionnement et accès non sécurisés.

La solution

  • Interface React responsive avec tableau de bord et visualisation des mouvements.
  • API REST Node.js sécurisée (JWT, validation, gestion des rôles).
  • Persistance PostgreSQL avec schéma relationnel et transactions.

L'impact mesuré

Saisie fiabilisée, alertes de stock automatiques et workflow CRUD complet opérationnel de bout en bout.

04

Rendre un assistant IA fiable sans aucune connexion internet

Problème Solution Impact

Le problème

Les assistants IA dépendent de modèles cloud et d'une connexion : inutilisables hors ligne, lents, et générant du code non vérifié, parfois sans rapport avec la demande.

La solution

  • Modèle LLM local (Qwen2.5-Coder-1.5B) avec tous les appels en mode local_files_only=True.
  • Boucle agent Plan → Exécuter → Observer → Replanir avec vérification et réparation du code.
  • Fallback contextuel (login → vraie page de login, etc.) et fine-tuning LoRA sur 4 665 échantillons.

L'impact mesuré

100 % hors ligne, code pertinent et vérifié, binaire portable Windows / Mac / Linux sans dépendance réseau.
